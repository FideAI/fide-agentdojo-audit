# Corrections and contributions

Describe the claim or row at issue, the pinned source version, your expected result and a minimal reproduction. Separate observed behavior from historical attribution and proposed fixes. Do not submit raw private records or live credentials.

Substantive corrections should update the claim ledger, affected prose/figures, changelog and verification expectations together. Preserve previous release tags and document whether the change is arithmetic, interpretation, code behavior or source scope. Do not silently replace prior released outputs. New experiments should declare selection, exclusions and falsifying outcomes before inspection when possible.

Keep paid inference, live-target tests and execution of historical payloads out of this reproduction workflow. Contribution review is not an assurance that a benchmark repair preserves every task's semantics.
